# Loki Doki — Full Codebase Audit (2026-07-11)

Scope: security, auth/multi-tenancy, dead code, performance, correctness, operational
resilience, and cross-platform installability (fresh Mac + Windows). Backend is
Bun + Hono (`backend/src`), frontend is React/Vite (`frontend/src`).

## Verdict

The codebase is **mature and unusually disciplined** — SSRF guard, session auth,
CSRF, admin PIN throttling, WAL + busy_timeout, boot guards, bounded queues,
stderr draining, and a gold-standard SSE catch-up primitive are all real and hold.
There is **no SQL injection, no path traversal, and no classic IDOR** — nearly every
per-user query correctly filters by `userId`.

The genuine problems cluster into a handful of **repeating patterns**, each with
several instances. Fixing the pattern once and sweeping the instances closes most
of the risk. Typecheck: both frontend and backend pass (backend has ~24
`noUncheckedIndexedAccess` warnings in `src/tools/`, mostly false positives).

## CRITICAL — can crash the whole server or enable RCE

### C1. Spawned ffmpeg with no `error` handler → uncaught exception → `process.exit(1)`
`routes/youtube.ts:1633` (1080p+ remux on `GET /stream/:videoId`), `routes/plex.ts:193`
(music transcode). Both register `close`/abort handlers but no `proc.on('error')`.
A ChildProcess `error` event (missing binary — `ensureFfmpeg()` deliberately never
throws and falls back to bare `'ffmpeg'`; or transient `EMFILE`) becomes an uncaught
exception, and `index.ts:446` responds by exiting the process. **One user pressing
play can take down the whole household.** Fix: add `proc.on('error', …)` that logs
and returns 502 / falls back to the progressive path.

### C2. Clipper: authenticated SSRF + yt-dlp argument injection (plausible RCE)
`routes/clipper.ts:82` → `lib/clipper/stream.ts:56` / `resolve.ts:50`. `/api/clipper/
resolve|save|stream` take a **raw pasted URL** and pass it to yt-dlp as a bare
positional arg — no `^https?://` check, **no `--` option terminator** — then `/stream`
`fetch()`es the resolved URL and **streams the body back to the caller**. Two bugs:
- **Readable SSRF** bypassing the app's own guard: `?url=http://169.254.169.254/…`
  or `http://localhost:11434/…` returns internal responses to any logged-in member.
- **Argument injection**: a value starting with `-`/`--` is parsed by yt-dlp as an
  option. Chained with `POST /api/drop/send` (deterministic path under `data/drops/`),
  `url=--config-location=<path>` loads arbitrary yt-dlp options incl. `--exec` → command
  execution.

Fix: reject non-`^https?://`; `assertPublicUrl()` the input **and** the yt-dlp-resolved
URL; add a `'--'` token before the URL in every yt-dlp/ffmpeg argv (also defensively in
`videoStream.ts`, `youtube.ts`, download-job paths).

## HIGH — security, hangs, pool starvation

### H1. SSRF via plain `fetch` bypassing `safeFetch` (a whole class)
Every finding here is the same root cause — a URL fetcher that uses plain `fetch`
instead of the project's `safeFetch`/`assertPublicUrl`. Two independent security passes
agreed on this list:
- **Shopping resolve/track** — `lib/shopping/fetch.ts:61,66` (`followRedirect`) and
  `lib/scrape.ts:53` (`fetchHtml`), reached from `POST /api/shopping/resolve|products|
  products/:id/listings`. Page title/price/description is **returned to the caller** →
  internal-service exfiltration. HIGH.
- **Feeds add/import** — `routes/feeds.ts:74` + `lib/feeds/poller.ts:111`. An explicit
  `body.feedUrl` **bypasses** `discoverFeeds` (which is guarded), gets stored, and the
  poller does a plain `fetch(feed.url)`. OPML `xmlUrl` too. MEDIUM (blind + partial
  reflection via `/items`).
- **Home-inventory AI photos** — `routes/home.ts:650` plain `fetch`. Blind SSRF
  (image-only, written to disk). MEDIUM.
- **LoRA import** — `routes/adminImageLoras.ts:885` pre-checks `assertPublicUrl` then
  `fetch(redirect:'follow')` → a validated host that 302s internal is followed. LOW (admin).
- **Media image proxy** — `lib/titles/imageProxy.ts:62` allowlisted host but follows
  redirects. LOW (theoretical).

Fix: route all through `safeFetch` (which re-validates every redirect hop). Mostly
one-line swaps.

### H2. Bookmark reverse-proxy serves remote HTML same-origin with framing/CSP stripped
`routes/proxy.ts:89`. The proxy (SSRF-guarded — that part is fine) serves rewritten HTML
from the **app's own origin** at `/api/proxy/:id/` while deleting `x-frame-options`,
stripping inline CSP `<meta>`, and setting no CSP. Any script in a proxied page runs in
the app origin → can call `/api/*` with the victim's cookie (CSRF origin check passes
because Origin *is* the app). A **global bookmark** (`ownerId=null`) is proxied by every
member → one malicious bookmarked page = household-wide account takeover. Fix: serve from
a cookieless sandbox origin, or set `Content-Security-Policy: sandbox` and iframe-sandbox
without `allow-same-origin`; don't strip upstream CSP.

### H3. Un-timed / un-pooled subprocess & fetch spawns → hangs and global pool starvation
The single largest cluster (confirmed by resilience + correctness passes). There is **no
shared fetch-timeout wrapper**; each call site owns its own timeout, and these missed it.
The correct templates already exist in-repo: `lib/videos/ytdlpJson.ts:24` (slot + hard
timeout + SIGKILL) and the two-phase Ollama stream guard.

Request-path fetches with no timeout (a stalled dependency hangs the request forever):
- **Ollama embed/list/delete** — `llm/ollama.ts:108` (`ollamaEmbed`, on the companion-turn
  hot path via router/RAG), `llm/ollama.ts:81` (`ollamaList`, bare `fetch(url)`, backs 5+
  handlers), `routes/models.ts:34` (delete). Add `AbortSignal.timeout(8–15s)`. **Highest
  blast radius** — every companion turn embeds.
- **Reddit + Vimeo provider layer** — `lib/videos/providers/reddit.ts:93,96`,
  `redditAuth.ts:39`, `vimeo.ts:103` (fans out to ~10 sites) and `:277` (bare; `:211` has a
  timeout — inconsistent). Thread `AbortSignal.timeout` through `redditJson`/`vimeoApi`.
- **Interactive TTS** — `lib/voice/engines/kokoroEngine.ts:19`, `synthSpeech.ts:52` pass
  only the caller signal (podcast path + whisper use 30s). Wedged sidecar → `/api/tts/
  stream` never emits, voice UI frozen with no error.

yt-dlp/ffmpeg spawns with no wall-clock timeout, several **bypassing the 6-slot pool**
(fork-bomb + pool-starvation risk — a wedged process eats a global slot until restart):
- **`lib/bookmarks/archive.ts:37`** (`capturePageMedia`) — `stdio:'ignore'`, no kill timer,
  job `_signal` never wired; inside `withYtDlpSlot`. Scheduled re-archives re-run it → a few
  hostile pages exhaust the pool → every interactive resolve/save hangs. Not stall-watched.
- **`lib/videos/download.ts:39`** (`runProcess`) — kills only on abort, no idle timeout;
  `video-media` not in `STALL_WATCHED_TYPES`; the reddit HLS path (`:129`) runs `ffmpeg -i
  <hls>` with no `-rw_timeout` and no progress callback → stalled CDN hangs ffmpeg forever.
- **`lib/youtube/durations.ts:34`** and **`download.ts:334`** (`ensureTranscript`) +
  `summarize.ts:271` — unpooled, un-timed. `backfillDurations` is `await`ed in a request
  handler (`routes/youtube.ts:403`) → wedge hangs the HTTP request; `ensureTranscript` is
  awaited by `plex-sync` (not stall-watched) → parks the job permanently.
- **`lib/clipper/stream.ts:28` / `resolve.ts:52`** — `-J`/`-g` on arbitrary user URLs,
  pooled but no wall-clock kill → can pin all 6 slots.

Fix: route every one through `ytdlpJson.ts`'s template (slot + `TIMEOUT_MS` + SIGKILL);
add an idle-timeout to `runProcess`; add `video-media`/`bookmark-archive` to the watchdog.

### H4. Explicit "Stop" can't abort the LLM during prefill — GPU + chat slot held for minutes
`lib/companionTurn.ts:861`. The main turn stream starts without a `cancelRef`; cancel is
only a cooperative `if (signal.aborted) break` *inside* the chunk loop, which can't run
until the first chunk — i.e. after the **entire prefill** (3–18s tool-heavy, up to 300s
cold load). Nothing destroys the socket. Two stuck cancels occupy both chat-lane slots and
block every user's chat/voice turns. Fix: pass a `cancelRef`, widen
`CompanionTurnHandlers.signal` to a real `AbortSignal`, wire `abort → cancelRef.cancel()`,
and check `aborted` before starting the stream.

### H5. Frontend: `/api/browser-session` SSE reconnects every ~1s during music playback
`frontend/src/hooks/useBrowserSession.ts:114`, root cause `context/RadioContext.tsx:202`.
The open-EventSource effect deps are `[navigate, radio]`; `useRadio()`'s memo changes
identity every second (`positionSec` tick) while a station plays → cleanup disposes and
reopens the managed EventSource once per second for the whole session. Device/controller
commands arriving in the gaps are silently lost; defeats the exact churn `manageEventSource`
exists to prevent. Fix: depend on `[]` and read `radio`/`podcast`/`navigate` via refs (the
file already does this for `reportAlive`).

### H6. Frontend: toggling hands-free OFF during engage leaves the microphone live
`frontend/src/hooks/useHandsFree.ts:568`. `micRef.current` is assigned only *after*
`engage()`'s awaits (wakeword load, mic-permission prompt). Toggle off during that window →
`disengage()` never runs, the hook goes fully live (mic capturing, wake loop on) while the
UI shows off, until the user toggles again. **Privacy issue.** Fix: call `disengage()`
unconditionally on `!enabled`.

## MEDIUM — data loss, silent-wrong, leaks

### Check-then-act races (guard before `await`, commit after)
- **`routes/adminArchives.ts:71`** — `has()` guard in handler, `set()` inside deferred
  `streamSSE` callback → StrictMode double-mount runs `downloadArchive()` twice on the same
  file and breaks `/cancel`. Fix: `set()` synchronously right after `has()`.
- **`routes/chat.ts:533,647`** — `/regenerate` and `/edit` check `findActiveByMeta` before
  several awaits, enqueue after → two jobs run in one conversation (chat lane = 2). `/edit`
  can also generate against messages being deleted under it. Fix: re-check synchronously
  before `enqueue`.
- **`lib/youtube/assets.ts:302`** — `releaseAssetsIfOrphaned` locks `assetid:${id}` while
  saves lock `assetLockKey(sourceId,kind,format)` — different keys → a save can be stranded
  at `pending` forever when its asset is deleted mid-flight. Fix: take `assetLockKey` (or both).
- **`routes/shopping.ts:370,553`** — SELECT → multi-second scrape → INSERT with
  `unique(retailer,externalId)` → concurrent trackers throw UNIQUE and leave an orphaned
  product row with no listings. Fix: `onConflictDoNothing` + re-select; roll back the product.
- **`context/GenerationContext.tsx:263`** — in-flight guard set after `await fetch` →
  double-click Generate queues two jobs writing one `GenState`. Fix: synchronous flag.
- **`routes/setup.ts:92`** — unauthenticated first-run admin creation has a check-then-act
  window allowing two admins. `download_jobs` has no unique index on `(type,variantKey)` →
  every `enqueue*` SELECT-then-INSERT can double-enqueue (reachable from the polled lyric-
  align self-heal → duplicate minutes-long compute jobs).

### "Listener on an already-aborted signal never fires" (leaked streams/downloads)
- **`lib/aria2.ts:214`** — cancel a ZIM/model job while inside `ensureAria2()` (minutes when
  brew/apt-installing) → aria2c spawns already-aborted, downloads the full multi-GB file to
  completion, rejects only at `close` hours later. Fix: `if (signal.aborted) reject` at top.
- **`routes/musicRadioLive.ts:177`, `podcasts.ts:795`** — abort listener attached after
  `await safeFetch` (10–30s) → a tab closed during connect leaves a never-ending ICY stream
  open (the comment calls this cancel load-bearing). Fix: check `signal.aborted` after fetch.

### Swallowed errors reported as success
- **`hooks/useHomeLayout.ts:81`** — `save` never checks `res.ok`, then `setLayout(next)`. A
  401/403/500 exits edit mode showing "saved"; reverts on reload. Fix: `throw` on `!res.ok`,
  toast in `saveEdit`.
- **`routes/youtube.ts:584`** — `syncPlaylistsForUser().catch(()=>{})` then unconditional
  `{ok:true}` → Plex down returns success with nothing synced (the adjacent `/sync-all` was
  rewritten to fail loudly for this reason). Fix: drop the swallow, return 502.
- **`routes/notifications.ts:20`** — `NOTIF_TYPES` is missing `price_alert`, `file_drop`,
  `service_alert` (in the schema enum) → muting those is silently a no-op and `POST` 400s
  valid types. Fix: derive from `notifications.type.enumValues`.
- **`routes/companions.ts:261`** — overlay `run` has no try/catch (unlike `makeChatRun`) →
  raw internal error text (DB paths, SQL) streamed to the client as the SSE error event.
- **`lib/pod/brain.ts:45`** — `runCompanionTurn().finally()` with no rejection handler until
  `await turn`; if the Pod session tears down early, a later reject is unhandled. Fix:
  `.catch(()=>{})` a defused reference.

### Poller / job correctness
- **`lib/videos/feed.ts:56`** — `lastFetchedAt` advanced only on success → a permanently
  failing follow sorts to the head of the due-list every tick and is retried forever; ≥20
  broken follows starve all healthy follows (auto-save stops for everyone). `feeds/poller.ts`
  correctly stamps on failure. Fix: stamp `lastFetchedAt`/`lastAttemptAt` in the catch.
- **`memory/judge.ts:334,359` + `sweep.ts:166`** — a Phase-2 throw (flaky Ollama) rejects
  after some facts were written; the `MAX_JUDGE_RETRIES` cap counts only Phase-1 failures, so
  the span retries every 5 min forever, and the dedupe-failure catch defaults to ADD →
  duplicate memories accumulate. Fix: count throws against the cap; default dedupe failure to
  NO_CHANGE when similar memories exist.
- **`routes/musicStudio.ts:132`** — track inserted `analysisStatus:'pending'` but the analyze
  job only enqueues `if (isStemAudioInstalled())` and never re-enqueues → permanent spinner
  after the runtime installs. Fix: insert `'none'` when the runtime is absent.

### Truncation / cache poisoning / disk leaks
- **`routes/videoStream.ts:43`** and the vstream cache — yt-dlp/ffmpeg write directly to the
  final path; `rm` cleanup runs only on clean non-zero exit → a restart mid-download leaves a
  truncated `.mp4` that `existsSync` treats as a valid hit forever. Fix: write to `.tmp`,
  atomic `rename` on success.
- **`lib/content/store.ts`** — `data/content/tmp` staging dir is **never swept** (gcSweep
  reclaims blobs only, boot doesn't clear it). Every failed/aborted download (yt-dlp partial
  fragments, abort, crash) leaks multi-GB files with timestamped names forever. Writers:
  `youtube/download.ts:128`, `videos/download.ts:121`, `youtube/live.ts:157`,
  `books/offline.ts:192`, `podcast/offline.ts:179`. Fix: boot + periodic sweep of entries
  older than a few hours.
- **`lib/bookmarks/render.ts:55`** — `installManagedChromium` (`bun x playwright install`)
  has no timeout → a stalled ~150MB download leaves the memoized promise pending forever, so
  all bookmark archives + Canvas PDF exports hang. On failure it caches `null` permanently →
  even after an admin repairs Chromium, archives silently degrade to static until restart.
- **Frontend `lib/mediaAudioGraph.ts:49`** — every graph is added to a module-level strong
  `Set liveGraphs` and never removed (the `WeakMap` GC assumption is defeated) → every
  `<video>`/`<audio>` that ever got a graph is leaked for the tab's life (10 biquads +
  crossfeed each, still connected to destination). Fix: store `WeakRef`s, prune in `applyDsp`.
- **`_downloadUrlImpl` `lib/download.ts:275`** — `fileStream.write(value)` ignores backpressure
  (no `drain` wait) → a 5–25GB model over gigabit onto a slow NFS/USB data root balloons RSS
  → OOM. This is the primary path for all model/binary downloads. Fix: `if (!write) await
  once(stream,'drain')`.

### Frontend state
- **`context/PodcastPlaybackContext.tsx:76`** — `lastSaved` never reset on episode switch →
  resume position silently lost for every episode after the first if the tab is killed. Fix:
  reset `lastSaved.current = 0` in `playTrackAt`; use `Math.abs` for backward seeks.
- **`lib/music/stemEngine.ts:209`** — no `onended` on playback → transport stuck "playing"
  over silence at end of a Studio/Karaoke track. Fix: attach `onended` to the longest buffer.
- **`lib/voice/voice-playback.ts:127`** — `finally` calls `releaseFetchSlot()` unconditionally
  but only `singleSentence` acquired → breaks the `MAX_PARALLEL_SENTENCE_FETCHES=2` cap. Fix:
  track `acquired` and release only then.

## AUTH / MULTI-TENANCY

One real item; the rest are confirmed-correct or by-design.
- **MEDIUM — Pod device endpoints keyed only by MAC, unauthenticated.** `routes/pod.ts:66,
  93,134,155,173` (`/display/:hwid`, `/display/:hwid/stream`, `/image/:hwid`, cover/atlas).
  Each resolves by `hwid` (MAC) with no session check → if the server is internet-exposed,
  anyone can enumerate low-entropy MACs (known ESP32/M5Stack OUI prefixes) and pull a live
  JPEG of a member's ambient screen (family photos, presence, now-playing) + device photos.
  Fix: authenticate these polls with the per-device pairing token instead of the bare MAC.
- INFO/by-design: Home Inventory (`routes/home.ts`) is household-shared (no per-user scope);
  `POST /api/auth/select` grants a session for any PIN-less non-admin profile (fine on LAN,
  risky if exposed); `/api/pod/audio/:file` and `/users/:id/avatar` are unauthenticated but
  non-sensitive. Confirm the single-household + trusted-LAN assumptions hold for the
  deployment; document that internet exposure requires PINs on every profile.

## PERFORMANCE

Top wins first (biggest impact per line changed):
1. **8.5 MB / 2.48 MB-gzip entry bundle.** Only Maps/Imaging/Admin/Music are `lazy()`
   (`App.tsx:118`); ~150 other pages are static imports, and maplibre-gl, @xterm, full
   refractor/prism, katex, and DiceBear collections all sit in the entry chunk every cold
   load (and every post-deploy SW reload) parses — seconds of main-thread stall on the
   tablets/kiosks this project targets. Fix: extend route-level `lazy()` to the remaining
   page groups; `MarkdownRenderer.tsx:6` → `PrismLight` + `registerLanguage`.
2. **maplibre-gl imported in `main.tsx:6`** just to register `pmtiles://` → hoists ~800KB
   into the entry chunk and defeats the MapsPage split. Fix: register in the MapsPage chunk.
3. **SQLite at `synchronous=FULL` with per-row commit loops.** `db/index.ts` never sets
   `PRAGMA synchronous=NORMAL` (WAL's recommended setting); only one `db.transaction` exists
   in the whole backend. Playlist reorder does one UPDATE per track (200-track drag ≈ 200
   fsync'd commits ≈ 200–400ms event-loop stall) — `routes/musicPlaylists.ts:279`,
   `ytPlaylists.ts:170`, clone loops `:315/:227`, `bookmarks.ts:68`, `privacy.ts:161`. Fix:
   `PRAGMA synchronous=NORMAL` (one line, speeds every write) + batch `values([...])` +
   wrap loops in transactions.
4. **Frontend pollers that never gate on visibility** (violates the project's own convention):
   Music Browse/Stations poll offline status every 5s forever — `MusicBrowsePage.tsx:79`,
   `MusicStationsPage.tsx:27` (copy the conditional `refetchInterval` from
   `lib/music/useOffline.ts:12`); `useNotifications.ts:88` is a raw 30s `setInterval` per
   consumer (4 mounts) never visibility-gated (make it one shared `useQuery`);
   `youtube/useData.ts:17` re-fetches the entire unbounded `/api/youtube/downloads`
   (`routes/youtube.ts:411`, no `.limit()`) every 5s and renders every row unvirtualized.
5. **YouTube Takeout CSV import** (`routes/youtube.ts:236`) fires ~300 concurrent upstream
   refreshes (`void refreshSubscriptionFeed` per row) → starves everything + trips rate
   limits. Fix: batch-insert, then feed IDs through the serial poller.
6. Lower: `lib/ogImage.ts:16` + `lib/ttlCache.ts` lazy-expiry only (slow growth);
   `/api/img` `readFile`s whole images into a Buffer per request (`lib/imageProxy.ts:44`) —
   use `Bun.file` + ETag/304; chat re-masks every message on every GET (`routes/chat.ts:118`).

Already healthy (verified): 146 indexes cover the hot paths; session auth TTL-cached with
eviction; sync-exec avoided on request paths; pollers consolidated backend-side; turn-context
7-query burst TTL-deduped; SSE visibility-gated.

## OPERATIONAL RESILIENCE (beyond the timeout cluster in H3)

- **`lib/logger.ts:23`** — the log fan-out loop isn't wrapped; one throwing subscriber (dead
  `/api/logs` SSE writer) breaks the broadcast for all and throws inside the logger. Fix:
  try/catch per subscriber + prune dead ones (`comfyui.ts:62` already does this).
- **`routes/drop.ts:47`** — the presence stream's 30s ping races `drop` events from other
  requests on one SSE stream with no write queue → corrupted chunked framing. Fix: reuse
  `browserSession.ts`'s `writeQueue`.
- **Inline LLM SSE streamers** (`routes/home.ts:988`, `adminCompanions.ts:239`,
  `projects.ts:198`) don't thread abort into `ollamaChatStream` and send no heartbeat →
  full answer generated for a gone client; `adminCompanions.ts:243` writes in its catch with
  no `.catch` → unhandled rejection.
- **`tools/coding.ts:29`** — `claude -p` uses SIGTERM only (no SIGKILL escalation → a wedged
  agent survives its 5-min timeout), fired detached with no per-user cap.
- **`lib/pod/cameraTest.ts`** (ffmpeg singleton + infinite respawn loop) is not in
  `index.ts:418 stopSidecars()` → outlives the backend on graceful shutdown. No spawn site
  except `esphome.ts` uses process-**group** kill → yt-dlp/ffmpeg merge grandchildren survive
  parent SIGKILL.
- **Error-detail leakage** — `String(err)`/`err.message` in JSON bodies at
  `routes/narration.ts:53`, `recipes.ts:72`, `bookmarks.ts:797`, `logo.ts:34`,
  `booksGenerate.ts:236`, `podcastSubscriptions.ts` can surface upstream URLs / FS paths / SQL.
- **`stopSearXNG` `lib/searxng.ts:433`** uses `execSync lsof`/`pkill` (blocks the event loop
  up to 5s during weekly auto-update restarts) — `kiwix.ts` documents this exact anti-pattern
  and uses async.
- **No general rate limiter / 429 path.** Expensive endpoints (image gen, vision, LLM,
  downloads) are bounded by concurrency queues, not request rate. Fine for single-household;
  add per-user rate caps if ever exposed to untrusted clients.

Verified strong (no action): `unhandledRejection`/`uncaughtException` handlers installed;
global Hono `onError`; boot side-effects guarded behind `__appBooted`; corrupt ZIM/image
models quarantined before native readers; migrations idempotent; WAL + `busy_timeout=5000`;
temp-file/TTL/size sweeps comprehensive (drops, `/api/img`, karaoke stems, sessions, blob GC).

## CROSS-PLATFORM INSTALL (fresh Mac arm64 + fresh Windows)

**Bottom line: the core app boots on both OSes** — `bun install` succeeds on a clean Windows
box with no VS/compiler (Bun skips native lifecycle scripts; `node-pty` ships prebuilds); Bun,
Node, Python, ffmpeg, yt-dlp, aria2, the Maps JRE, and Windows kiwix-serve.exe are all
auto-provisioned with correct per-OS/arch branches; venv `bin/` vs `Scripts/` and POSIX tooling
are `IS_WIN`-guarded. **The failures are all at feature-provisioning / first-use time**, and
several kill a headline feature on a fresh box.

Tier 1 — breaks a headline feature, no graceful fallback:
1. **`git` is assumed on PATH with no managed fallback** — `lib/download.ts:1711` (ComfyUI
   clone), `lib/searxng.ts:293` (clone + weekly update), custom-node clones `:1584,:1758`. No
   `ensureGit` anywhere. Fresh **Windows** has no git → ComfyUI **image-gen and SearXNG search
   are dead on arrival**; fresh **Mac** `/usr/bin/git` pops the Xcode-CLT GUI dialog and
   fails an unattended setup. Directly contradicts the "everything else installs itself" doc
   claim. Fix: add `ensureGit()` (portable MinGit on Windows) or fetch GitHub codeload
   tarballs + `extractArchive` and skip git entirely.
2. **Offline Library (default-ON) can't provision on a fresh Mac** — `lib/kiwix.ts:143` runs
   `spawn('npm', ['install','@openzim/libzim'])` (node-gyp source compile needing npm + Xcode
   CLT), but this is a **Bun-only app with no npm**. Windows avoids it via prebuilt
   kiwix-serve.exe. Fix: download prebuilt kiwix-tools for macOS too; drop the compile.
3. **vtracer extraction shells out to `unzip`** — `lib/vtracer.ts:103`; the Windows asset is a
   `.zip` and `unzip` doesn't exist on Windows → the "SVG (vector)" image-gen output can never
   provision on Windows. Fix: use `extractArchive()` (as `libwebp.ts` does).
4. **GraphHopper config embeds Windows paths in double-quoted YAML** — `lib/maps/ghConfig.ts:20`
   — `"${pbfPath}"` with `C:\Users\…` → `\U`/`\d` are YAML escapes → SnakeYAML mangles the path
   → offline routing import fails on Windows. Fix: single-quoted scalars or `\`→`/`.

Tier 2 — niche arch / desktop build: win-arm64 has no torch/onnxruntime/essentia wheels
(`download.ts:1720`, `pyenv.ts:230` — surface an explicit "needs x64 Windows" message);
desktop `bun install` fails at Electron postinstall on Windows (`desktop/package.json:20` —
use `npm install` for that workspace in CI); Ollama asset selection is amd64-only for
